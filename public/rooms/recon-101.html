Introduction

Reconnaissance (recon for short) means gathering information about a target before you do anything else. In web security, it’s the first step for ethical hackers, penetration testers and, unfortunately, attackers too.

Why does it matter?

Because most breaches don’t begin with clever tricks. They begin with something simple that someone left lying around: a forgotten comment, an old backup, a page that was meant to stay private. If you can find it in five minutes, so can anyone else.

Where does this happen in real life?

Security teams run recon on their own websites to find leaks before attackers do. Bug bounty hunters get paid for reporting exactly this kind of exposure. Some serious breaches have started with a publicly reachable backup file nobody remembered existed.

An analogy

Imagine walking past a shop after closing time. You haven’t touched the door, but you can still read the opening hours, see the staff rota taped inside the window and spot a key hidden under a plant pot. Web recon works the same way: you look at what’s already visible, and you notice what shouldn’t be.

Stay legal

Only test systems you own or have written permission to test. In the UK, accessing a computer system without authorisation is a criminal offence under the Computer Misuse Act 1990. Everything in this room is a simulation, so you’re completely safe here.

Learning objectives

By the end of this room, you’ll be able to:

  • Explain what reconnaissance is and why defenders care about it.
  • Read a page’s source code and spot comments that reveal too much.
  • Explain what robots.txt does, and why it isn’t a security control.
  • Recognise an exposed directory listing.
  • Tell the difference between encoding and encryption, and decode Base64.

Idea 1: the page you see isn’t the whole page

Your browser turns HTML into the pretty page you see. The original HTML is still there, and anyone can read it (right-click, then “View page source”). Developers sometimes leave notes to themselves inside HTML comments. Comments look like this:

<!-- this text never appears on screen, but it's in the source -->

Comments are invisible on the page, but they aren’t secret. That’s a very common mix-up.

Idea 2: robots.txt is a polite sign, not a locked door

Search engines crawl websites. A file called robots.txt, always found at the top of the site, asks them to skip certain folders. Well-behaved crawlers obey. But the file is public, so it also hands a map of “interesting” folders to anyone who reads it.

robots.txt

Idea 3: directory listings

If a server isn’t configured properly, visiting a folder with no home page can show a list of every file inside it. That’s called a directory listing, and it’s a classic misconfiguration. Think of it as leaving the filing cabinet open with an index on top.

Idea 4: encoding is not encryption

Base64 turns data into letters and numbers so it travels safely through systems that only expect text. It’s like writing a message in a different alphabet: anyone who knows the alphabet can read it, and no key is needed. Encryption, by contrast, needs a secret key to reverse.

Plain text:  Hello
Base64:      SGVsbG8=

Demonstration

Let’s walk through a worked example on a different, made-up site, so you can see the method before you try it yourself. Imagine pagesandpens.example, a small online bookshop.

Step 1: read the source

<body>
  <h1>Pages & Pens</h1>
  <!-- TODO: delete the /test-orders/ folder after launch -->
</body>

The comment names a folder, /test-orders/. Nobody linked to it on the page, but now we know it exists.

Step 2: check robots.txt

User-agent: *
Disallow: /test-orders/
Disallow: /staff-rota/

This confirms the folder exists and reveals a second one, /staff-rota/. Ask yourself: if the owner wanted these hidden, why list them in a public file?

Step 3: note it and report it

An ethical hacker stops here, writes down what they found and tells the owner. The fix is simple: remove the comment, delete the test folder and protect anything private with a login. Recon found the problem without breaking anything.

Key takeaways

  • Recon is about noticing what’s already public, and it comes before any other security testing.
  • HTML comments are invisible on screen but readable by anyone.
  • robots.txt is a request to crawlers, not a lock. It can even point attackers to sensitive folders.
  • Directory listings and forgotten backups are common, avoidable misconfigurations.
  • Base64 is encoding, not encryption. Anyone can decode it.
  • Defenders use the same steps to find and fix problems first. Always get permission before testing.
